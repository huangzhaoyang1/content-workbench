# 评估集（eval）

本目录用于**回归评估**内容工作台的各 AI 能力：给一批预设问题，调用对应服务，
再把服务输出和「期望关键词」比对打分，从而量化每次改动后效果是否退化。

> 当前状态：**数据集、执行脚本（`eval_run.py`）与结果目录（`result/`）均已就绪**。

---

## 2. 数据格式：`eval_questions.json`

一个 JSON 数组，每条问题包含 3 个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | int | 问题编号（1–20），唯一 |
| `category` | string | 问题类别，取值见下表，用于路由到对应服务 |
| `question` | string | 输入给模型的自然语言问题（占位，可替换为真实样本） |
| `expected_keywords` | string[] | 期望在服务输出中**出现**的关键词；用于记分 |

### 类别与服务路由

| `category` | 中文 | 路由到的服务（占位映射） | 说明 |
| --- | --- | --- | --- |
| `dissect` | 拆解类 | `services/content/dissect.py` | 拆解抖音/视频文案 → 结构化 JSON + 公众号改写 |
| `topic` | 选题类 | `services/content/topic.py` | 选题生成 / 标题风格分析 |
| `hotspot` | 热点类 | `services/integration/hotspot.py` | 热点素材检索 → 洞察 + 切入角度 |
| `retrieval_history` | 检索历史类 | `services/data/analytics.py`（规划中） | 检索历史文章 / 阅读数据复盘 |

> 注：`retrieval_history` 对应的历史检索服务当前由 analytics/数据检索支撑，
> 执行脚本实现时需先明确其接口（占位，待补）。

## 3. 评估流程

```
┌─────────────┐    ┌──────────────────┐    ┌──────────────────────┐    ┌────────────┐
│ 读取问题集  │───▶│ 按 category 路由  │───▶│ 调用对应服务得到输出  │───▶│ 比对关键词 │
│ (JSON 文件) │    │ 到对应后端服务   │    │ (model output)        │    │ 记分      │
└─────────────┘    └──────────────────┘    └──────────────────────┘    └────────────┘
                                                                                  │
                                                                                  ▼
                                                                          ┌────────────┐
                                                                          │ 汇总报告   │
                                                                          │ (准确率等) │
                                                                          └────────────┘
```

逐步说明：

1. **输入问题**：从 `eval_questions.json` 逐条读取 `question` 与 `expected_keywords`。
2. **调用对应服务**：根据 `category` 把问题发给第 2 节表中对应的后端服务/接口，
   拿到模型输出文本（必要时先经过该服务的 Prompt 模板与 `.format()` 填充）。
3. **比对输出与 `expected_keywords`**：对每条问题的输出文本，检查
   `expected_keywords` 中有多少个关键词真实出现（子串匹配，简单可解释）。
4. **记分**：
   - 单条得分 = 命中关键词数 / 期望关键词总数（0–1）。
   - 类别得分 = 该类别下所有条目的平均分。
   - 总得分 = 全部 20 条的平均分。
5. **汇总报告**：输出每类准确率、总准确率，以及「未命中关键词」列表，便于定位退化点。

> 关键词匹配默认用**子串包含**即可，足够做占位回归；
> 后续可升级为：正则、同义词归一、或 LLM-as-judge（在脚本中实现）。
