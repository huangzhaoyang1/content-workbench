# UI 重设计说明（核心流程优先的工作台）

> 改造方向：核心流程优先的工作台——重构导航 + 新增统一首页 + 观感一致性。
> 现有页面与接口**保持可用，不重写设计体系**；仅做导航结构、首页内容、以及少量样式/标签层调整。
> 完成日期：2026-08-12

## 一、改了什么（总览）

| 阶段 | 改动文件 | 关键内容 |
|---|---|---|
| 一·侧边栏重排 | `frontend/src/components/layout/Sidebar.tsx` | 两级导航：核心流程（置顶，图标+大字号）＋ 更多（折叠组，默认收起）；保留活跃高亮；用挂载后读 `location.search` 的方式判断 `?review=1`，避免 `useSearchParams` 的 Suspense 约束 |
| 一·任务页支撑 | `frontend/src/app/tasks/page.tsx` | 新增「审核」深链（`/tasks?review=1`）→ 仅显示待审核任务；页头新增主操作「发起出稿」(→/topic)；审核模式横幅与退出按钮 |
| 二·工作台首页 | `frontend/src/app/page.tsx` | 重写为工作台首页：欢迎语(账号名)+后端状态 / 今日核心数据卡(待审核·今日完成·素材库) / 核心流程四步引导(拆→选→写→审) / 最近 5 个任务 |
| 三·观感一致性 | `frontend/src/app/dissect/page.tsx`、`topic/page.tsx` | 拆解页 H1 去掉 emoji 与首页/侧边栏统一；选题页流水线状态徽标「进行中」→「运行中」，与共享 `TaskStatusBadge` 标签对齐 |

> 三个 commit：`af92c4b`(侧边栏) / `5fb5124`(工作台首页) / `f81299a`(观感一致性)。

## 二、每个页面的新旧结构对比

### 1. 侧边栏（Sidebar.tsx）
- **旧**：9 个入口平铺一栏（概览/热点素材/爆款拆解/抖音收藏同步/数据分析/选题与生产/任务队列/历史任务/系统配置），无分组，描述文案全部常驻显示。
- **新**：
  - **核心流程**（置顶，图标 + 大字号 + 常驻描述）：工作台 / 拆解 / 选题 / 出稿 / 审核
  - **更多**（折叠组，默认收起）：热点 / 队列 / 数据分析 / 抖音同步 / 设置
  - 活跃高亮沿用原 `bg-sidebar-accent` 样式；「出稿」「审核」两个入口都指向 `/tasks`，靠 `?review=1` 区分，避免同时高亮。

### 2. 工作台首页（page.tsx）
- **旧**：通用「概览」——主行动区（去生成选题/先看热点）+ 队列待执行卡 + 最近 3 期 + 9 个快捷入口卡 + 推荐工作流长列表。内容多、跳转分散。
- **新**：
  - 顶部：欢迎语（按时间问候 + 账号名，取自鉴权 `realm`，取不到回退「内容运营」）+ 后端在线状态徽标。
  - 今日核心数据卡（3 张 `StatCard`）：待审核 / 今日完成 / 素材库——全部走现有接口，取不到显示「—」静默降级。
  - 核心流程四步引导卡（主视觉）：① 拆解爆款→/dissect ② 选入选题→/topic ③ 生成文章→/tasks ④ 审核发布→/tasks?review=1，步骤间箭头示意顺序。
  - 底部：最近 5 个任务状态列表（复用 `TaskStatusBadge` + 状态徽标）。
  - 旧版「快捷入口 / 推荐工作流」已折叠移除，相关入口由侧边栏「更多」承载，降低拥挤。

### 3. 任务页（tasks/page.tsx）
- **旧**：标题「历史任务」，页头仅「任务队列 / 刷新」。
- **新**：页头新增主操作「发起出稿」(`/topic`，primary 变体)；支持从侧边栏「审核」进入的 `/tasks?review=1` 深链——仅显示 `draft_status === PENDING_REVIEW` 的任务，并给出审核模式横幅与「退出审核模式」按钮。其余筛选/统计/列表/回收站逻辑未动。

### 4. 拆解页（dissect/page.tsx）
- **旧**：H1 为 `🎯 爆款拆解`（带 emoji）。
- **新**：H1 改为纯文本 `爆款拆解`，与其它页面 H1（选题与生产 / 历史任务 / 工作台）风格统一。

### 5. 选题页（topic/page.tsx）
- **旧**：流水线状态徽标用本地 `statusBadge`，`running` 显示「进行中」。
- **新**：`running` 标签改为「运行中」，与共享 `TaskStatusBadge`（ok/error/running/waiting）的文案对齐，消除同义异写。

> 拆解 / 选题 / 任务 / 任务详情四处的状态徽标语义已统一为：`成功=emerald`、`失败=red`、`待审核=amber(warning)`、`运行中/等待中=muted`，分别由 `TaskStatusBadge` 与共享 `Badge` 变体承载。

## 三、若仍不满意，可以再调的参数点

1. **侧边栏分组与默认展开**
   - 「更多」默认折叠（`MoreGroup` 内 `useState(false)`）。若想默认展开，改为 `true`。
   - 若要把某个「更多」项提到核心流程，直接在 `CORE` 数组里加一项即可，无需改其它逻辑。

2. **首页数据卡口径**
   - 「今日完成」目前取「当前拉取的最新 20 条任务里 completed_at 是今天的」(见 `isSameDay` + `page_size: 20`)。任务很多时可能漏算更早的今日任务——若要精确，可在后端加 `time_range=今日` 或前端分页累计。
   - 「待审核」「素材库」同样来自首屏一次拉取；如要更准，可把 `listTasks`/`dissectListTopics` 的 `page_size` 调大。

3. **首页四步引导样式**
   - 卡片纵向间距 `gap-3`、桌面横向 `md:flex-row`、箭头旋转 `rotate-90 md:rotate-0` 都在 `page.tsx` 的 `FLOW_STEPS` 渲染块，可直接调。

4. **审核模式覆盖度**
   - 审核模式在 tasks 页是对「已加载任务」做客户端过滤（`visibleTasks`），并非服务端按待审核分页。若待审核任务很多跨多页，建议后端加 `draft_status` 过滤参数，前端 `load` 透传。

5. **间距规范**
   - 全站内边距由 `PageShell` 统一（`lg:px-8 lg:py-10`）；区块间距首页用 `mt-6`、拆解/选题用 `mt-5`/`space-y-5`。若想完全一致，把 `mt-5` 统一成 `mt-6` 即可（纯样式，无风险）。
