# 后端功能与接口速查

> 面向「AI 内容运营工作台」后端（FastAPI）。聚焦已落地的**管理类功能**（第二阶段 + 5.1/5.2），
> 以及**统一错误格式**与**测试方式**。日常运行的完整 API 见 `backend/main.py` 的路由注册。

## 1. 怎么跑测试

后端测试用 pytest + pytest-cov，数据全部隔离在临时目录，**不会碰真实数据**。

```bash
# 依赖（一次性安装到项目运行的 Python 3.12）
python -m pip install pytest pytest-cov

# 在项目根目录执行
python -m pytest backend/tests -c backend/pytest.ini
```

- `backend/tests/conftest.py`：在导入 backend **之前**用临时目录覆盖
  `WORKBENCH_DATA_DIR` / `STREAMLIT_PROJECT_ROOT`，每个用例自动清场。
- 当前总覆盖率约 **35%**（核心 service / router / main 覆盖更高），21 个用例全绿。

## 2. 统一错误格式

所有错误都返回同一结构，前端 `api.ts` 依赖 `detail` 字段：

```json
{ "ok": false, "detail": "中文友好提示", "error": { "code": "http_404", "message": "中文友好提示" } }
```

- 路由层把业务异常 `DissectError` / `TasksError` 转成对应的 `HTTPException`
  （状态码沿用异常自带的 `status_code`：找不到类 = 404，校验类 = 400）。
- `main.py` 额外注册了 `DissectError` / `TasksError` / `HTTPException` / 校验错误 /
  兜底 `Exception` 处理器，确保**任何漏接的端点也不会掉到泛化的「服务端异常」**，
  而是把原始中文提示原样返回。

## 3. 选题库（`/api/douyin-dissect/topics`）

| 功能 | 方法 & 路径 | 说明 |
| --- | --- | --- |
| 保存选题 | `POST /save-topic` | 按标题去重；可带 `tags`（≤10） |
| 列表 / 筛选 | `GET /topics?tag=&keyword=&status=` | 支持按标签、关键词、状态过滤 |
| 单条 | `GET /topics/{id}` | 拿去生产 / 批量操作时用 |
| 局部更新 | `PATCH /topics/{id}` | 只传要改字段；正文变化会拍版本快照 |
| 批量删除 | `POST /topics/batch-delete` `{ids}` | 移入回收站，缺失 id 静默跳过 |
| 批量生产 | `POST /topics/batch-produce` `{ids}` | 逐个加入队列（带 `topic_id` 联动） |
| 标签列表 | `GET /topics/tags` | 全部标签（去重、按次数降序） |
| **回收站** | `GET /topics/trash` · `POST /topics/restore` · `POST /topics/purge` · `POST /topics/empty-trash` | 软删除可恢复 |
| **版本历史** | `GET /topics/{id}/versions` · `GET /topics/{id}/versions/{vid}` · `POST /topics/{id}/restore-version` | 正文回退，回退前先存当前版 |

## 4. 历史任务（`/api/tasks`）

| 功能 | 方法 & 路径 | 说明 |
| --- | --- | --- |
| 列表 / 筛选 | `GET /tasks?tag=&keyword=&status=` | 可按标签过滤 |
| 详情 | `GET /tasks/{issue}` | 含 `tags` |
| 设标签 | `PATCH /tasks/{issue}/tags` `{tags}` | 覆盖式；空列表即清空 |
| 标签列表 | `GET /tasks/tags` | 全部任务标签 |
| 批量删除 | `POST /tasks/batch-delete` `{issues}` | 移入回收站，缺失 issue 不报错 |
| **回收站** | `GET /tasks/trash` · `POST /tasks/restore` · `POST /tasks/purge` · `POST /tasks/empty-trash` | 软删除（`DELETE /tasks/{issue}` 现为移入回收站） |

> 任务标签存在独立 sidecar `task_tags.json`，刻意不碰流水线 `result.json`。

## 5. 队列 ↔ 选题库联动

- `POST /api/queue` 的 `add` 支持 `topic_id`；开工时 `_flip_topic` 把对应选题翻成
  「生产中」，成功翻「已完成」、失败回退「待生产」（可重试）。
- 翻转异常被 `try/except` 吞掉，**绝不拖垮流水线**。

## 6. 数据落盘位置

- 选题库 / 回收站 / 版本历史 / 任务标签：`DATA_DIR`（默认 `backend/data`，
  可用环境变量 `WORKBENCH_DATA_DIR` 覆盖）。
- 历史任务产出目录：`STREAMLIT_PROJECT_ROOT/data/issues/<N>`；回收站在同级
  `data/issues_trash/<N>`（可用 `STREAMLIT_PROJECT_ROOT` 覆盖）。
